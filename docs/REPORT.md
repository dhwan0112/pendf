# REPORT — penDF 현재 상태 (0.7.3, 2026-11-16)

버전별 변경은 [CHANGELOG.md](../CHANGELOG.md), 결정은 [DECISIONS.md](DECISIONS.md), 막힌 것은 [BLOCKERS.md](BLOCKERS.md), iPad 확인 절차는 [DEVICE_CHECKLIST.md](DEVICE_CHECKLIST.md)에 있다. 이 문서는 시간순 기록이 아니라 지금의 상태다.

## 한눈에

- 목표 문서의 6단계(뷰어, 하이라이트, 텍스트 주석, 링크, 북마크, 필기)와 추가 기능(기본 열기, 썸네일, 전체 검색, Pencil 상시 필기)이 모두 구현되어 있다. 최신 릴리스 **0.7.3**: 0.7.2의 핀치 줌(제스처 중 합성만, 한 번 커밋, 캔버스 메모리 프리셋)에 예산 루프·다크 모드 수정과 판정용 프리셋 *0.7.1 canvas cap*을 더했다.
- 0.7.3은 build·test(193)·lint·`smoke:webkit`과 **테스트 볼트 전체 하네스 33/33**을 통과한 뒤 태그했다. 하네스는 `scripts/harness-batches.mjs`로 12묶음에 나눠, 묶음마다 테스트 볼트 창을 다시 열고 메모리를 기록하며 돌렸다(아래 §6). 0.7.2는 32/32로 태그했다(첫 실행 29/32의 실패는 하네스 순서·시점 문제로 0.7.1에서도 같았음).
- 지난번 실패한 `ground-truth-same-pdf-embed`는 하네스 재시도 수정 뒤 통과했다(최종 빌드로 2회). 원인은 하네스가 느리게 열리는 PDF를 다시 연 것이었고 제품 문제가 아니어서 BLOCKERS에는 올리지 않았다(D-37).
- **iPad에서는 아직 아무것도 확인되지 않았다.** 데스크톱(Obsidian/Chromium)과 Obsidian 밖 WebKit에서만 검증했다.
- B-06은 테스트 볼트에서 재현되지 않았다(수정 전 빌드로도). SciWiki 고유 조건으로 열어 둔다.

## 0.7.2 — 핀치 줌의 검은 번쩍임과 끊김

측정은 모두 하네스 `zoom-gesture`(테스트 볼트, `long-300.pdf` 5쪽, 합성 두 손가락 터치·Ctrl+휠, 데스크톱 Obsidian/Chromium)다. "iPad 프로필"은 `devicePixelRatio` 2와 penDF의 모바일 렌더 설정을 데스크톱에서 흉내 낸 것이고 iOS 자체가 아니다. 기준선은 0.7.1 코드 그대로(`docs/evidence/zoom-baseline-0.7.1-*.json`, iPad 프로필은 0.7.1의 모바일 값 2^23), 수정 후는 `docs/evidence/zoom-after-0.7.2.json`.

### 2. 설계 변경 (D-38, D-39)
1. 제스처 중에는 `.pdfViewer`의 CSS transform만 바꾼다. pdf.js 호출·레이아웃 읽기·레이어 작업 없음. 배율과 미리보기 위치는 커밋 뒤 닿을 수 있는 범위로 묶는다.
2. 손을 떼면 한 작업 안에서: transform 제거 → 배율 한 번 → pdf.js의 동기 `scalechanging` 안에서 손가락 아래 점을 맞추는 스크롤과 화면 밖 캔버스 해제 → 레이어 동기화. 커밋 뒤 pdf.js가 쪽 상자를 픽셀 격자에 맞추며 생기는 몇 px는 그 쪽이 그려질 때 다시 맞춘다.
3. 옛 캔버스는 새 캔버스가 완성될 때까지 남는다(재렌더가 취소돼도, 빌드 변환 규칙). 캔버스 아래 종이색 배경.
4. 캔버스 메모리: 프리셋(Default / Memory saver / No detail canvas / pdf.js defaults)과 예산.
5. 데스크톱: 트랙패드 핀치는 연속 합성, 휠 한 칸은 10% 한 단계(포인터 고정).
6. 계측: HUD(`canvasMB`, `zoomPreset`, `lastZoom`), 로그 요약, 명령 *Export last zoom timeline to vault*(프레임 간격, 렌더, 캔버스 생성·해제, 메모리 피크, 기준점 오차), 진단 모드의 빈·검은 캔버스 표본.

### 4. 기본 프리셋: Default (잠정)
- 쪽 캔버스 상한을 pdf.js 자신의 iOS 값(5,242,880 px)으로 되돌렸다. 0.7.1의 2^23은 이보다 60% 크다. iPad DPR 2의 쪽 폭 맞춤이 대략 이 값이고, 더 확대하면 pdf.js의 상세 캔버스(보이는 부분만)가 선명도를 맡는다.
- 상세 캔버스를 켜 둔다(끄면 확대 시 흐림. 메모리도 줄지 않았다: 60.2 MB).
- 화면 밖 캔버스 해제와 160 MB 예산을 더했다: 같은 상한에서 pdf.js 혼자일 때보다 피크가 낮다(47.9 vs 65.0 MB).
- 검은 화면이 iOS 메모리 때문인지는 데스크톱에서 가릴 수 없으므로, iPad 비교(DEVICE_CHECKLIST 7-3) 뒤 확정한다. 그때 앱이 꺼지거나 검게 번쩍이면 *Memory saver*가 후보다.
- **원인 판정(0.7.3, D-40):** 진단용 프리셋 *0.7.1 canvas cap*(모바일 2^23 px, 예산 없음, 커밋 때 해제 없음, 나머지 수정은 그대로)과 *Default*를 iPad에서 비교한다(DEVICE_CHECKLIST 7-9). 0.7.1 cap에서만 검게 번쩍이면 원인은 iOS 캔버스 메모리(A), 둘 다 괜찮으면 원인은 0.7.2에서 고친 투명 배경·캔버스 삭제·멈춘 사이 재렌더였다. 이 프리셋은 진단용이며 기본값으로 쓰지 않는다.
- **주의할 점:** 가로 화면 iPad의 쪽 폭 맞춤은 5,242,880 px를 넘을 수 있다. 그러면 pdf.js가 기본 캔버스 해상도를 반으로 낮추고 상세 캔버스에 기댄다. 그것이 흐려 보이면 더 큰 상한의 모바일 프리셋이 지금은 없다(필요하면 추가).
- **0.7.3 수정:** 0.7.2의 예산은 화면에 있는 것보다 작으면 pdf.js가 미리 그린 다음 쪽을 해제→재렌더하는 루프에 빠질 수 있었다(예산 2 MB 강제 시 유휴 4초에 렌더 554회, iPad *Memory saver*에서 가능). 보이는 범위 앞뒤 쪽을 보호해 고쳤다(유휴 렌더 0회). 다크 읽기 모드에서 캔버스가 아직 없는 쪽이 흰색으로 보이던 것도 고쳤다(D-39).

### 5. iPad에서 할 일
DEVICE_CHECKLIST **7장**(7-1~7-9):
1. Debug overlay를 켜고 `long-300.pdf`에서 핀치(천천히·빠르게·멈췄다 계속)를 다른 기기의 240fps 슬로모션으로 찍는다.
2. 핀치마다 명령 **penDF: Export last zoom timeline to vault** → `pendf-zoom-*.json`을 가져온다.
3. 설정 → Diagnostics → Zoom rendering을 네 프리셋으로 바꿔 가며 1·2를 반복한다.
4. **원인 판정(7-9):** *Default*와 *0.7.1 canvas cap (diagnostic)*으로 같은 핀치를 10번씩 하고 비교한다. 끝나면 *Default*로 되돌린다.
5. Default로 최대 확대 후 1분 동안 스크롤·확대·축소를 반복해 앱이 꺼지지 않는지 본다.
결과 파일들을 주면 기본 프리셋과 예산을 확정한다.

### 6. 0.7.3 전체 하네스와 메모리
- 12묶음(2~3개씩), 묶음마다 테스트 볼트 창만 닫았다 다시 열었다(다른 볼트 창은 건드리지 않음). 상태를 묶음마다 저장해, 중단되면 통과한 묶음은 건너뛰고 나머지만 잇는다.
- Obsidian 전체 프로세스 작업 집합: 묶음 시작 940~980 MB, 끝 993~1,092 MB(창을 다시 열면 매번 시작 수준으로 돌아옴). 시스템 여유 메모리 6.25~7.9 GB(전체 31.3 GB). 이번에는 중단 없이 끝났다. 묶음별 수치는 증거 파일의 `batches[].memBefore/memAfter`.

## 알려진 한계

- 하네스: 플러그인을 끄고 켠 직후 Obsidian이 뷰를 다시 만드는 동안 연 탭은 빈 뷰로 남을 수 있다(D-37). 하네스는 다시 연다. 실패한 실행 뒤 Obsidian CLI가 그 창에서 응답하지 않으면 테스트 볼트 창을 닫았다 다시 연다.
- 0.7.2의 "확인한 원인"은 데스크톱 Obsidian과 Playwright(WebKit/Chromium)에서의 확인이다. 검은 프레임 자체는 수정 전에도 후에도 데스크톱에서 재현되지 않았다.

- 노트 안 PDF 임베드와 호버 미리보기는 Obsidian 자체 뷰어가 그린다(공개 API로 바꿀 수 없음).
- 기본 열기 때 코어 뷰어가 잠깐 보이고 탭 전환이 2회 일어난다(전체 로드는 1회, D-35).
- 다른 플러그인이 코드로 연 PDF 링크, 빠른 전환기로 연 PDF는 기억된 위치로 열린다(누른 링크 기록이 없으므로).
- 표준 글꼴이 PDF에 없고 기기에도 맞는 로컬 글꼴이 없으면 브라우저 기본 대체 글꼴로 그린다(D-33, 대안 `useSystemFonts: false`).
- 필기: 필압 없음(모노 펜), Pencil로 글자 선택 불가(상시 필기 켜짐 시), 예측 이벤트 미사용.
- 데스크톱은 개발·디버깅용(마우스 필기는 필기 모드에서만).
